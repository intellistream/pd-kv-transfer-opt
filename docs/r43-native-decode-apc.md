# r43 双侧 APC 原生基线

## 部署与验证

Qwen3.5-35B-A3B BF16，两台 8 卡 910B2，2P2D，每实例 Attention TP4、Expert EP4、DP1。与 r42 实际命令比较，只给 D 启用本地 APC 和 `additional_config.recompute_scheduler_enable`。保持 P APC、P 原生图策略、D `FULL_DECODE_ONLY`、4,096 分块预算、16 槽、最大上下文 262,144、原生 MooncakeConnectorV1 与 AscendStoreConnector。D 主机池是 128 GiB。参数以 `cybber695` 发布并核对的远端树启动，两侧日志仍为 `enforce_eager=False`，两个 D 实例均报告 `AsyncRecomputeScheduler`。[远端配置提交](https://github.com/intellistream/pd-kv-transfer-opt/commit/5d591893ca8c7adc03c797068b44ad43dad27398) · [官方 A2 参考](https://docs.vllm.ai/projects/ascend/en/v0.30.0/tutorials/models/Qwen3.5-397B-A17B.html#56-prefill-decode-disaggregation-a2)

推理服务就绪后先走原生代理，重复短输出验证成功流和 D 命中。随后在固定 P/D 实例对上让 P 每次使用新的测试命名域，同时分别复用或切换 D 命名域。两个 D 每次暖测试均增加 35,840 个本地命中 token，冷测试零命中。各流均完整返回 16 个 token。相同贪心输入的候选分数接近时出现 token 分叉，冷测试的重复观测也有分叉。在带分数的 4 个探针配对中，3 个冷暖配对发生分叉，分叉处各轮的第一、第二候选分数差最多 0.125。该检查确认原生交接、实际命中与流完整性。正式回放保留自然 EOS 并记录实际输出，短检查的数值波动随实测一起归档。

四臂复用 r42 原物化 `e9e915f126adc1f09517b4b3741f4c3e1caa4c4e1fd53899b81e9a6ddda09281` 和同一投放清单。48 会话、254 个请求、根投放至 92.5 秒。输入指纹、前驱、实际生成预算、EOS、原生路由均经过核对。每臂 Store 为零键，P/D 使用独立的臂内缓存命名域，代理重新初始化。正式吞吐对照只切换 D 八口出站限额，按 `100→200→200→100` 运行，Get/P 批次和 D 就绪的详细方法采样单独进行。[r42 来源和计量](r42-natural-sustained.md)

## 逐请求归因

- 正序升档少生成 12,831 token，完工提前 40.19 秒。沿会话前驱替换观测阶段，P HTTP 对应 5.29 秒，D 首 token 后对应 32.76 秒。末会话从 `fix-ocaml-gc` 变为 `crack-7z-hash`。正序 100 档的末会话从 35 秒释放，从 P 到 D 的链上累计 P HTTP 20.08 秒，D 首 token 后 488.61 秒。其末条请求只生成 107 token。最后一个 P 回包后 1.54 秒结束这轮，前几轮的 D 生成仍决定了后继何时能进 P。
- 反序升档少生成 4,574 token，完工提前 45.57 秒。P HTTP 抵消 22.73 秒，D 首 token 后对应 70.00 秒的提前。末会话从 `crack-7z-hash` 变为 `winning-avg-corewars`。相同 200 档的输出只多 982 token，时间却缩短 125.00 秒，D 首 token 后对应 127.39 秒。这给出了压尾会话变化以及整轮吞吐的同档波动。
- 把首 token 后驻留分成实际输出数和每 token 有效驻留，并对会话完工重算。正序的 40.19 秒提前拆为首 token 前 +7.44 秒、逐条输出量 −28.90 秒、每 token 驻留 +61.65 秒，正值表示提前。反序分别为 −18.57、+117.53、−53.39 秒。相同 200 档的 125.00 秒差中，逐条输出量对应 +142.28 秒。整轮输出的增减与最终末链上实际输出的变化方向可以不同。实际 P/D 去向在正序配对 67/254 条、反序 63/254 条相同，有效驻留也包含组批与路由变化。
- 四臂 D 的 MAC 接收是 451.92–523.14 GB，同源 r42 曾为 924.97–963.46 GB。r43 的 D 引擎均记录实际本地命中。MAC 收包涵盖原生 KV 交接及其他流量，逐向载荷以独立方法记录为准。

复算使用 `pd_kv_transfer_opt.profiling.profile_closed_sessions`，逐请求对齐流式计数、API usage、P/D 代理阶段和会话依赖。归档含远端树指纹、热/冷测试回执、逐臂限额和缓存清理。正式四臂退出后已确认两台 16 卡空闲，D 八口恢复实验前值。[版本和收尾回执](../results/2026-11-20-r43-native-decode-apc/manifest.json) · [隔离短测](../results/2026-11-20-r43-native-decode-apc/isolated-apc-scores.json)

## 独立方法采样与瓶颈判定

详细采样使用同一份 254 条请求，分别覆盖 P 的 IPC、分块、Store 和 ADXL，以及 D 的本地前缀分配、Mooncake 交接提交和 KV 就绪。两档各完成 254/254。分方向载荷按原生描述符累加。D→P GET 的 Store 与 ADXL 字节在每一笔上对齐，P→D 只累计 `native_transfer_submit`。D 的 MAC 计数和两项载荷的统计范围各自保留。[方法数据与逐请求记录](../results/2026-11-20-r43-native-decode-apc-methods/summary.json) · [采样版本与校验值](../results/2026-11-20-r43-native-decode-apc-methods/manifest.json)

- 实际执行中，GET 同步等待主要落在 ADXL 的原生传输服务区间。该区间包含底层提交和等完成。两档共 484 笔 GET 均有对应 ADXL 观测且无负返回。100 档比 200 档多读 34.89 GB；全组调用分位数同时受字节和调用组成影响。同请求、同实际 P/D、同字节及调用数匹配到 6 条，100 档最慢 rank 的 GET 中位多等 108 ms。`circuit-fibsqrt:37` 的 GET 从 303 ms 降到 144 ms，P HTTP 从 21.01 秒增至 26.88 秒。局部等待变化没有在匹配请求中稳定传到下游。
- 100 档首轮的 P API 至 ADD、ADD 至实际入队、IPC 队列三级 p50 分别为 15.8、21.0、92.1 ms。P 冷首轮的长秒级等待主要发生在接纳后至首块派发。按单请求 4,096-token chunk 对齐，已有历史分为 0–32K、32–96K、96K 以上时，100 档派发到批结果的 p50 为 422/495/640 ms，200 档为 421/494/657 ms。rank 0 设备 forward 分别为 185/221/289 ms 和 185/220/298 ms。以批形状和历史长度做条件比较，两档的计算段接近。P 两档记录的 1,461/1,515 个批均报告 `PIECEWISE` 图回放。
- 100 档在首次 KV 就绪后，D0 有 4.69 秒无就绪请求且有 P 工作在途，D1 为 0。200 档为 4.69/12.01 秒。两档这些空档与单口或聚合达 85% 的采样窗口重叠均为 0。方法采样中的 200 档少输出 8,044 token，提前 4.26 秒完工，整轮总吞吐下降 2.59%。
- 100 档有 65 条请求实际回读，260 笔 GET 是这 65 条各四个 rank 的调用。合并 260 笔的重叠区间后，整轮只有 16.70 秒至少有一笔 GET 在执行，即 3.91%。一条发生回读的请求平均读取 2.06 GB，维持 100 Gbps 需要约 6.06 条这样的实际恢复每秒，实测整轮平均为 0.152 条/s。两档实际 D→P GET 分摊到输出分别为 **0.594/0.456 MB/token**。按先前独立高压诊断的双 D 约 1,154 token/s 作量级估算，同样的恢复组成折合约 5.48/4.21 Gbps 的均衡持续需求。八口均衡打满 100 Gbps 在该生成率下需约 10.83 MB/token。此估算用于筛选负载，短突发和热点口仍按原事件与逐口计数判定。[恢复需求量级模型](problem-model.md#瓶颈归因与模型校验)
- 冻结逐条输出、实际路由与其他观测阶段，在会话模型里将 100 档各请求最慢 rank 的同步 GET 时间归零，完工提前 0.28 秒，吞吐 **527.78→528.13 token/s**。再用更宽的假设，把每条 P HTTP 与其同实例 GET 活跃窗口的重叠也设为零，对应提前 2.48 秒、**530.86 token/s**。D 分配至就绪归零对应 **528.14 token/s**。将所有 D 首 token 后的驻留缩短 10%，模型给出 **574.81 token/s**，整轮提前 34.99 秒。驻留含生成、组批和等待；该重放量化观测路径的敏感性，改动组批后要重新模拟资源反馈。

原负载已观测到局部同步传输等待，并确定等待在方法内的位置。端口和 D 供给缺少 100 档持续受限并卡住整轮的交叉证据。当前有依据的下一步是增加同源负载的会话到达强度，保持双侧 APC 和真实 EOS，继续量实际回读。
