# r44 提高自然长会话到达强度

## 设置

r43 的原生带宽对照缺少持续的 D→P 回读压力。r44 用已发布的同一份双侧 APC 2P2D 配置提高到达强度。运行参数逐实例与 r43 一致，P→D 是 MooncakeConnectorV1 拉取，D→P 是 AscendStore 同步 GET。共享池由 D 的八个 rank 提供合计 128 GiB。详细方法采样的结果见 [r43](r43-native-decode-apc.md#独立方法采样与瓶颈判定)。

将 r42 的 48 条原始会话链完整复制到两个独立租户命名域，根计划相差 1.25 秒。共 96 个回放会话、508 条请求，源内容仍是同一批 48 个 Terminal-Bench 2.1 任务。每次回放保留原 prompt token 指纹、前驱、工具间隔、EOS、生成预算和上游原生路由。会话后继等前一条真实结束，两臂都从已排空的引擎和零键 Store 开始，分别使用独立臂命名域。持续投放段每秒计划新根约从 0.4 增至 0.8，最后一条根计划位于 93.75 秒。两个租户共用引擎和物理缓存容量，各自在命名域内进行正常的前缀复用。两臂固定同一个工作量文件指纹 `df7c71b0acddd71aa1d86fe819963d5407f487cb9bc46107610b09e701c4ba3a`。仅 D 八口的聚合出站上限在臂间切换。[源数据与原投放](r42-natural-sustained.md#会话和度量)

原工作量累计输入 1,707.55 万 token，放量后 3,415.10 万。按每会话最大输入计，两个租户的前缀体量约 629.72 万 token。128 GiB 对应最多约 335.54 万 Attention token 的跨 rank 原生载荷，还需为 Hybrid 状态和其他 KV 预留实际占用。上述量级用于解释缓存竞争，活跃工作集以实际进度和驻留状态判断。[原生载荷与各组对齐](ascend-hybrid-prefix-restore.md#单独核对跨机字节与整轮完工)

## 放量改变了什么

| 指标 | 100 Gbps | 200 Gbps |
|---|---:|---:|
| P 实算输入 token | 33,313,930 | 33,532,042 |
| P 本地 APC token | 789,504 | 618,496 |
| P 实际外部恢复 token | 47,104 | 0 |
| D 本地 APC token | 7,439,360 | 8,161,280 |
| D 外部交接 token | 26,711,178 | 25,989,258 |
| Store 成功驱逐批次 / 累计被驱逐字节 | 256 / 1,693.81 GB | 260 / 1,719.15 GB |
| Store 分配失败计数 / 批量启动失败计数增量 | 11,498 / 823 | 10,116 / 827 |
| P 首轮 / 后继 HTTP p50 | 84.17 / 160.11 s | 77.34 / 162.06 s |
| D 首轮 / 后继 HTTP 至首 token p50 | 0.355 / 0.348 s | 0.314 / 0.322 s |
| P0 / P1 等待队列峰值（请求） | 43 / 52 | 50 / 47 |
| D0 / D1 无运行或等待、同时有 P 在途 | 32.74 / 24.27 s | 40.39 / 30.00 s |

- 对照 r43 正序 100 档，P 实算从 539.96 万升到 3,331.39 万 token，外部恢复从 252.01 万降到 4.71 万。放量后两档约 97.6%/98.2% 的 P 输入 token 走实算，D 仍有本地 APC。两个 P 的 worker 均实录 `-200` 写入空间不足。D 的 master 在约 92%–96% 占用观测到内存驱逐。Store 计数涵盖多次分配尝试和后台写入，客户端仍完成全部请求。容量压力、回读缩减和实算增加同时发生，具体哪些前驱的键在查找前被逐出仍需逐键关联。[容量日志摘要](../results/2026-11-20-r44-native-intensity/native-capacity-logs.json)
- 投放窗的 55 个根在两档实际发出。100/200 档各有 76/82 个请求实际发出，P 回复 25/31 个。两个 D 平均只有约 3–4 条运行请求，实测无工作且有 P 请求在途的区间与端口热点的交集均为 0。P 的长等待和带宽余量同时存在，放量形成的主要是 P prefill 供给压力。
- 两档的压尾会话分别是第二个租户的 `fix-ocaml-gc` 与 `crack-7z-hash`。100 档的末链累计经过 566.48 秒 P HTTP 和 556.15 秒 D 首 token 后驻留。200 档对应 817.47 秒和 290.94 秒。对称替换各请求的实测服务时，200 档 P HTTP 阶段使终点变晚 88.52 秒，D 首 token 后阶段抵消 87.54 秒，其余阶段合计抵消约 0.16 秒。508 条中，实际 P/D 去向一致的有 112 条，实际输出长度一致的有 62 条。

冻结实际输出与其他阶段，削减 100 档的整个 P HTTP 10% 对应 **373.90→393.08 token/s**，削减 D 首 token 后驻留 10% 对应 **389.03 token/s**，扣除与已采样端口热窗的交集仍为 **373.90 token/s**。200 档同样的两项阶段条件回放为 **386.28／368.29 token/s**，原始是 **359.10 token/s**。这些是在原会话图上的阶段敏感性。r44 的正式计时采样保留 P HTTP 包络，方法级分解沿用独立 r43 证据并注明负载条件。

本轮根到达翻倍后，Store 驻留和 P 冷算改变了真正可读的工作量。带宽机制的判据应以查找时可恢复的缺页字节、最慢 rank 的同步等待及下游工作供给为依据。当前观察没有达到 RDMA 优化实机对照的进入条件。[模型与判定](problem-model.md#瓶颈归因与模型校验)

## 归档

回放事件与限速回执按 `profile_closed_sessions` 重算。两次硬限速读回与缓存初态已核对，收尾已恢复 D 八口到实验前的 200 Gbps/口，两台主机 16 卡空闲。保存了合并清洗轨迹、工作量指纹、Store 压力日志摘要和释放回执。[归档清单](../results/2026-11-20-r44-native-intensity/manifest.json)
