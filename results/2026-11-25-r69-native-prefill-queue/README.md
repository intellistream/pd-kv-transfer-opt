# r69 原生四轮的 P 首块派发前等待

使用 2026-11-25 原生双侧 Store 的四轮 r69，覆盖两台各八卡 910B2、2P2D、Attention TP4、Expert EP4、DP1。两端各八口分别限 **每端聚合 100/200 Gbps**，对应逐口 12.5/25 Gbps。四轮各完成 106 条请求，共 424 条，保留双侧 APC、原生路由与自然 EOS。源归档的八份 SHA-256、逐条输出、路由及结束时刻与原有实测包核对一致。 [实验配置和正式吞吐](../2026-11-25-native-2p2d/README.md)

从 P HTTP 发出到首块派发的等待平均为 17.22–21.62 秒，约占各轮 P HTTP 请求秒的 82–85%。正序和反序 100 Gbps 下，等待中分别有约 90.0% 和 91.2% 与同 P 的其他在途 prefill 重叠，且对应区间无观测到的同步 Store GET。此处每个并发等待请求各自计时。同一 P 的 4.78 秒停顿就可对应 76.49 请求秒，整轮优化空间仍取决于关键链。两对提高带宽均缩短 D 侧交接等待，正式含排空吞吐分别变化 +3.45% 与 −3.23%。 [按轮分解及占比](queue-summary.json) · [路由、吞吐与压尾归因](bandwidth-attribution.json)
